Pascal's Triangle

By the end you will build each row from the one above it, using nested loops, and print it as a neat triangle. About 25 to 30 minutes.

1. Understanding the problem

Pascal's Triangle is a pyramid of numbers. pascal_rows(n) returns the first n rows as a list of lists, top row first. Row numbers here start at 0, so the top row [1] is row 0 and row i holds i + 1 numbers.

Rule: a row starts and ends with 1. Every number in between is the sum of the two numbers directly above it (up-left and up-right) in the previous row. The ends are the exception because they only have one number above them.

For n = 0 the answer is an empty list. The function returns the rows and prints nothing, so the data can be tested and reused; showing it as a triangle is a separate job done outside.

  • Nested loops, building each row from the previous row.
  • No factorials or formulas, no math, no list comprehensions, no imports.
  • Print the triangle outside the function, adding the leading spaces yourself (no .center()).

2. The prerequisite idea: lists inside a list

A list of lists holds rows. An index is a position number starting at 0. grid[1] is the second row; grid[1][0] is the first item in that row. A negative index counts from the end, so grid[-1] is the last row.

grid = [[7], [8, 9]]
print(grid[1][0])        # one row, then one item
grid.append([4, 5, 6])   # add a whole row at the end
last = grid[-1]          # the most recent row
print(len(last))         # how many items it holds

Size rule: row i has i + 1 numbers, two of which are the 1s at the ends. So only i - 1 spots need a sum.

4. Translating it into Python

Step 1: A place to collect rows, and one pass per row.

What does the result start as (think of n = 0), and what should the outer loop count over?

RevealIt starts as an empty list, so n = 0 returns [] with no special case. The loop runs once per row, with row numbers 0 up to n - 1.

PseudocodeMake an empty list for rows. Repeat once for each row number from 0 to n - 1.

Step 2: Start the new row.

What do all rows have in common at the front?

RevealThey begin with 1, so the new row can start as a list holding just that.
Stuck?
NudgeRow 0 is only this.
Bigger hintMake a fresh list each pass. If you reuse the previous list, you will change the old row too.
Pseudocodenew_row = a brand new list containing the number 1.

Step 3: Fill the middle from the previous row.

When is there a previous row at all? Which spots need a sum, and which two items do you add for spot j?

RevealFrom row 1 onward. Spots 1 up to row number - 1 need a sum, adding positions j - 1 and j of the previous row.
Stuck?
NudgeUse P3: which spot numbers did the sums fill?
Bigger hintThe previous row is the last row you stored. Remember range stops before its second number.
PseudocodeIf this is not the first row: take the last stored row as prev. For j from 1 up to the last middle spot: add prev at j - 1 plus prev at j to new_row.

Step 4: Finish the row and store it.

How does a row (after row 0) end, and where does the finished row go?

RevealIt ends with 1, added after the sums. Then it is appended to the rows list.
Stuck?
NudgeBoth ends of a row are 1, but row 0 has only one number.
Bigger hintAdd the ending 1 only when there is a previous row, inside that same check. Store every row, including row 0.
PseudocodeAfter the middle: add a 1 to the end of new_row. Then add new_row to rows. When the loop is over, give back rows.

Common beginner mistakes

  • IndexError: list index out of range. The inner loop reaches too far, or it runs on row 0 where there is no previous row. Check the last j against P3.
  • Rows are missing the last 1, or every row has the wrong length by one. Compare row 2 with [1, 2, 1] and count the numbers.
  • Wrong number of rows. The outer loop is off by one, so print len(result) for n = 3.
  • n = 0 gives [[1]] instead of []. The container started with a row already in it.
  • Old rows change or repeat. The new row is the same list as the previous one. Make a fresh list each pass.
  • Results keep growing between calls. The rows are stored outside the function. The "again" test catches it.
  • It prints and returns None. Remove the print and return the list.

6. Reflection

Each row is built only from the one before it: a 1 at each end, and sums of neighbours in between. A loop over rows holds an inner loop over spots, and displaying the result is a separate job from computing it.

Q1. Why can't the two end numbers use the same "add two above" rule?

RevealThey only have one number above them (the other side is outside the triangle), so there is nothing to add. That is why they are fixed at 1.

Q2. Why does the inner loop do nothing for rows 0 and 1, and why is that fine?

RevealRow i needs i - 1 sums, which is 0 or fewer for those rows, so the range is empty and the loop body never runs. They are just the ends, which is correct.

Q3. What do you gain by returning the rows instead of printing them inside the function?

RevealThe data can be tested with ==, reused (to print, count or look up a number), and displayed in different ways, such as the triangle shape, which depends on n and not on how rows are built.
