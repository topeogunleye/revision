Tower of Hanoi: recursion as a recipe

By the end you will write hanoi() yourself and trust each smaller call to do its job. About 25 to 30 minutes.

1. Understanding the problem

Picture three pegs and n disks of different sizes stacked on one peg, smallest on top. You must move the whole stack to another peg, one disk at a time, taking only the top disk of a stack. The three pegs have jobs: source (where the stack starts), target (where it must end) and helper (a spare parking spot).

Rule: never put a larger disk on top of a smaller one. That is the whole difficulty: without it you could just hop every disk to the target.

Your function moves nothing. It returns a list of moves in order, each move a pair (from_peg, to_peg). Returning (not printing) matters because a list can be counted, compared and tested, while printed text just disappears.

  • Recursive, with no loops inside hanoi.
  • No print inside it, and no imports.
  • Outside it: print the move count for n = 1 to 10 and spot the pattern.

2. The prerequisite idea: a recipe that calls itself

A recipe can say "add the sauce (see the sauce recipe)". A recursive function does the same: it asks itself to solve a smaller version and uses the answer. Two parts make it work. The base case is a version so small you answer it directly, with no further calls. The recursive call hands a smaller problem to the same function, and you trust it to return the right answer, without tracing how.

def count_down(n):
    if n == 0:               # base case: nothing left to do
        return []
    return [n] + count_down(n - 1)   # my piece + the smaller answer

move = ("A", "C")            # one move: a pair (a tuple)
moves = [move]               # a list holding one move
both = [("A", "B")] + [("B", "C")]   # + joins two lists into one

3. How it works, by hand

Here is the given 3-disk example, one move at a time. Disk 1 is the smallest. Green = the disk that just moved.

Look at move 4, the only move of disk 3. Where are disks 1 and 2 at that moment? What do moves 1 to 3 and moves 5 to 7 have in common?

RevealDisks 1 and 2 are stacked on B. Moves 1 to 3 carry the two small disks out of the way; moves 5 to 7 carry them back on top. Each group is a smaller Tower of Hanoi where the pegs play different jobs. Your function never needs to know how the small tower moves, only that a call can do it.

Practice by hand

P1 (easy). Write the moves for hanoi(2, "A", "C", "B").

Reveal[("A","B"), ("A","C"), ("B","C")]. Small disk to B, big disk to C, small disk onto C.

P2 (medium). Take the 3-disk answer from the problem but with pegs named X, Y, Z: hanoi(3, "X", "Z", "Y"). Write the first and last move.

RevealBoth are ("X","Z"). The answer is the given one with A→X, B→Y, C→Z. Peg names are just labels.

P3 (harder). Without running anything: how many moves for 4 disks, and which move number carries disk 4?

Reveal15 moves: 7 to clear the way, 1 for the big disk (move number 8), 7 to put the tower back.

Five small tasks. Try each question before opening anything.

Step 1: The base case. The smallest problem you can answer without any call.

What is the smallest tower, and what list of moves does it need?

RevealOne disk needs one move, source to target. (Zero disks needing an empty list also works. Pick one.)

Step 2: Clear the way. Get the smaller tower off the biggest disk.

Where must the n−1 smaller disks sit so the biggest disk can move? For that smaller job, which peg is start, end and spare?

RevealThey can't stay on source (the big disk is under them) or go to target (the big disk lands there), so they go to the helper. In that job, source is the start, helper is the end, target is the spare.
Stuck?
NudgeCheck move 4 in the stepper again.
Bigger hintThis is the same puzzle with n−1 disks, so call hanoi again. The three names you pass in decide each peg's job.
Pseudocodefirst_part = the moves that carry n−1 disks from source to helper, with target as the spare.

Step 3: Move the biggest disk. Exactly one move.

How is one move written, and how do you make it joinable with other lists?

RevealA pair of the peg names you were given, wrapped in square brackets so it is a one-item list (see quiz 1).
Stuck?
NudgeThe biggest disk goes from where it is to where it must end.
Bigger hintYou already have both peg names as parameters.
Pseudocodemiddle_part = a list containing one pair: from source, to target.

Step 4: Put the smaller tower back. One more trusted call.

The n−1 disks now sit on one peg. Where do they start and end this time, and which peg is the spare?

RevealStart on helper, end on target, with source as the spare.
Stuck?
NudgeCompare with step 2: which pegs swapped jobs?
Bigger hintThe peg the small tower came from is now empty and free to use as the spare.
Pseudocodelast_part = the moves that carry n−1 disks from helper to target, with source as the spare.

Step 5: Join and return.

How do three lists become one, and in which order?

RevealJoin with +, in the order the moves actually happen: first part, middle part, last part.

Common beginner mistakes

  • RecursionError: maximum recursion depth exceeded. The chain never reaches the base case. Check that every call passes a smaller n, and that your base case covers where n lands. (The optional n = 0 test fails this way if your base case is n == 1.)
  • TypeError mentioning NoneType or a tuple and a list. A branch forgot to return, or a single move is not wrapped in [ ].
  • Right number of moves, wrong pegs. Two peg names are swapped in one recursive call. Redo P1 by hand and compare.
  • A list inside a list. You joined pieces in a way that nested them. Print one result and look at the brackets.
  • Results grow every time you call it. The moves are stored somewhere outside the function. That breaks the pure-function rule; the "n = 2 again" test catches it.
  • It prints and returns None. Remove the print and return the list.

6. Reflection

Recursion means solving the biggest piece yourself and trusting the same function for the smaller copy, as long as a base case stops the chain. Here that gave: clear the way, make one move, rebuild. Move counts follow from the same shape.

Q1. When you wrote the call for n−1 disks, how could you trust it without tracing it?

RevealIt is the same function, so if it is right for the base case and each step builds correctly on a smaller answer, it is right for every n. You only check one level at a time.

Q2. Why do the two recursive calls pass the peg names in different orders?

RevealThe pegs change jobs: the small tower first travels source to helper, and later helper to target. Each call needs the right start, end and spare.

Q3. What pattern did your counts show, and why must it happen?

RevealEach count is double the previous one plus 1, which equals 2n − 1. The two recursive calls each cost the previous count, and the biggest disk adds one move.
